## 0. 一句话目标

把 auto_timetable 从 DSH 插件形态（单用户 + 本机服务 + DSH 对话桥）独立为面向全国大学生的全端智能时间表产品：**微信小程序 + Windows PC 端 + Windows 桌宠（Live2D 虚拟形象）**，AI 自然语言编辑课表 + 云同步，个人主体免费上线，商业化后置。

## 3. 现状盘点（DSH 依赖面 → 独立要改什么）

真正依赖 DSH 的只有三处，其余均为可迁移自有资产：

1. **AI 对话桥**：手机页「对话」标签 → mobile-server → 本机 DSH 会话。独立后 = 云函数网关直连 LLM API（key 只存服务端）。
2. **wechat_monitor**：PC 微信监控投 DSH。产品形态下用户电脑没有 DSH，入口改为小程序内自然语言/拍照。
3. **部署拓扑**：cloudflared 免费隧道 + 笔记本 7×24 + PIN 单用户。产品化 = 云服务 + 微信登录 + 按用户隔离的多租户数据（现有 schedule.json 单文件单用户假设推翻）。

**可迁移资产**：
- `occur.js`（UMD 纯 JS，领域核心单一实现）→ 抽为 `packages/core` npm 包，小程序（npm 构建）/云函数/Electron 三端共享
- `mobile.html` + `mobile-app.js` 的 UI 语义与交互（周/日视图、编辑对话框、提醒）→ 小程序端平移蓝本
- `.qrtest/occur-test.mjs` 114 例表驱动用例 → 核心包的回归基线
- `tt.mjs` 的日期解析约定与「AI 禁止心算日期」纪律 → 沉淀为 AI 网关的系统提示词规范
- 桌面端 helper.py（maliang）经验、Android TWA 壳经验 → 桌面/分发参考

**全新模块**：Electron 桌宠（透明窗/置顶/拖动/提醒播报）+ Live2D 渲染（参考开源：git2968/Desktop-pet、Rosa134/daidai-live2d-pet、Open-LLM-VTuber，不得闭眼照搬——须做选型对比）。

## 4. 架构基线（Phase 1 计划的输入，可被有理推翻）

```
新独立 monorepo（与 auto_timetable 自用仓分离；产品名待定，暂占位 TT-Suite）
├─ packages/core        # 领域核心 JS 单实现（occursOn/validate/deadline 约定），三端共享
├─ apps/miniprogram     # 微信小程序（复用手机页 UI 语义；npm 构建引 packages/core）
├─ apps/desktop         # Electron：PC 主应用 + 桌宠透明窗（Live2D）
├─ cloud/               # 微信云开发：云函数（账号/同步/AI 网关）+ 云数据库
└─ shared/              # AI 提示词、日期纪律文档、类型定义
```

- 后端优先**微信云开发/云托管**（免自建服务器、免单独域名备案、按量计费；MVP 期成本量级约每月几十元，估算口径以官方计费页为准）
- AI 网关 = 直连 DeepSeek/GLM 官方 API：key 不下发客户端；每用户日配额 + 总量熔断。**回复形态已定（2026-09-21 用户拍板）：云托管容器 + SSE 流式**（表 B 选 B2，体验对齐现有手机页流式对话；容器常驻成本使月预算高于原「≤100 元」口径，量级以云托管计费页实测为准，估算口径）
- 多租户数据模型：微信 openid 为主键，课表按用户分文档存储；现有事件 schema（weekly/once/custom/task、skip、weekPattern、跨午夜 end<start）原样继承

## 5. 验收标准（每条可测）

1. **核心包**：114 例 occursOn/validate 用例在新包全绿；同一份课表 JSON 在小程序与 PC 端渲染一致（周视图逐列块数对账，参照 landscape-week-test 口径）
2. **小程序闭环**：微信登录 → 云同步 → 自然语言改课表（AI 网关）→ 周/日视图 → 课表截图/文本 AI 导入 → 订阅消息提醒，全流程可用
3. **PC 端**：Electron 应用可安装运行，同账号数据与小程序一致（云同步双向）
4. **桌宠**：Live2D 形象驻留桌面（透明窗/置顶/可拖动），日程提醒到点桌宠气泡/动作播报
5. **AI 网关**：key 不出现在任何客户端代码（可 grep 验证）；每用户日配额生效（超额明确降级提示）
6. **合规**：小程序 ICP 备案通过；隐私政策与用户授权流程在位；AI 输入输出过内容安全接口（msgSecCheck 或等价）
7. **成本可见**：云托管 + 云开发 + LLM API 月成本可从控制台账单核对（B2 流式形态含容器常驻成本，具体量级以云托管计费页为准，估算口径）

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 个人主体 + 面向全国：增长期 API/云成本失控 | 每用户日配额 + 全量熔断 + 灰度放量；账单监控 |
| AIGC 合规（微信对 AI 生成内容有安全要求） | 输入输出双过内容安全接口；拒绝词兜底 |
| 个人主体小程序可选类目受限 | 上线前核对「工具-效率」类目资质要求 |
| 大学生课表录入摩擦（竞品靠教务导入） | AI 解析课表截图/粘贴文本为主入口；教务对接列非目标 |
| 双端同步做周期长 | 里程碑硬切分（M0 核心包 → M1 双端闭环 → M2 桌宠 → M3 公测），每段独立可验收 |
| 桌宠 Windows 兼容性（透明窗/性能/杀软误报） | 参考成熟开源实现 + 真机矩阵测试 |

## 7. 里程碑骨架（Phase 1 细化为带判据的计划）

- **M0 核心抽包**：monorepo 脚手架 + packages/core 迁移 + 114 例回归绿
- **M1 双端闭环**：小程序（登录/同步/AI/视图/提醒）+ PC 端（Electron 主应用 + 云同步）
- **M2 桌宠与形象**：Electron 透明窗 + Live2D 集成 + 提醒播报
- **M3 公测准备**：备案/隐私/AIGC 安全/配额熔断/灰度 + 数据看板
- **商业化（M4 后置）**：免费攒用户 → 验证留存 → 升级个体工商户开微信支付 → 会员（AI 额度/形象/主题）或买断（参考 WakeUp 口碑路线 vs 番茄ToDo 会员路线，届时用数据定）
